# Настанови щодо внеску

Дякуємо, що розглядаєте можливість внеску! Як вбудований проєкт з обмеженими ресурсами, ми балансуємо між новими функціями й використанням флеш-пам'яті/RAM та навантаженням на процесор.

## Швидка схема рішень

- **Виправлення помилок** → **Дуже вітаються**
    - виправлення безпеки, збоїв чи коректності;
    - бажано з мінімальними кроками відтворення або регресійними тестами.
- **Зовнішні/автономні застосунки** → **Дуже вітаються**
    - код, що не споживає внутрішню флеш-пам'ять;
    - не змінює основні API системи (лише додає, не ламає).
- **Зміни основної системи** → **Спершу обговорення**
    - зміни архітектури (радіо, компіляція, файлова система тощо);
    - навігація та інтерфейс;
    - основна функціональність (послідовний порт, керування файлами, редактор тексту, менеджер частот, налаштування й налагодження, постійна пам'ять тощо).

    **Обов'язково:** відкрийте **Issue** або запитайте в **Discord** перед написанням коду. Ми можемо відхилити зміни, що споживають багато RAM/флеш заради рідкісних випадків. Рання відповідь уникає марних зусиль.

## Після злиття pull request

Додайте статтю у вікі: створіть нову сторінку або оновіть наявну з описом вашої зміни (покращення, новий застосунок). За потреби оновіть бічне меню. Це тримає документацію актуальною й полегшує іншим розуміння проєкту.

## Політика щодо коду з AI

- **Вітається** за умов:
    - ви маєте перевірити, що код працює на **реальному обладнанні** (не лише компілюється);
    - ви готові доопрацьовувати за зауваженнями ревʼю.

## Загальні вимоги

- Дотримуйтеся наявного стилю коду (запускайте `clang-format`).
- Додавайте `static` для внутрішнього зв'язування; мінімізуйте глобальні символи.

Роблячи внесок, ви погоджуєтеся з [ліцензією](https://github.com/portapack-mayhem/mayhem-firmware?tab=GPL-3.0-1-ov-file#readme).
