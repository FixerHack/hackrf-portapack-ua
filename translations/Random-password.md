# Rand Pwd (генератор паролів)

![Rand Pwd на пристрої](annotated/app-101.jpg){ width="360" }

*Скріншот з пристрою: [Утиліти](Screens-Other#shot-101).*

Це [зовнішній застосунок](External-apps-informations) (файл `.ppma` на SD-карті).

Застосунок використовує демодульовані дані AFSK як випадкові «зерна» (seeds) для кожного символу, а як генератор псевдовипадкових чисел — LCG плюс ще один шар випадковості.

Теоретично, якщо якість «зерен» (здебільшого це радіошум) достатня, паролі будуть достатньо випадковими. Але зазвичай це не так, або ми цього не знаємо, або якість нестабільна. Тож навіть якщо це безпечніше за багато інших генераторів і в найкращому разі може вважатися справжнім генератором випадкових чисел, **не використовуйте його для високих вимог безпеки**, наприклад для фінансових справ.

Усі кнопки/прапорці «send» у застосунку означають надсилання через асинхронні повідомлення послідовного порту — див. [USB Serial Console](USB-Serial-Console).

Режим **Flood** безперервно транслює згенеровані коди в послідовний порт; також можна позначити прапорець збереження, щоб зберігати коди й «зерна». Пам'ятайте: маючи «зерна», можна відтворити той самий код відповідним генератором — тож вони так само секретні, не розголошуйте їх.

## Як користуватися

1. Дочекайтеся, поки заповниться буфер «зерен» (рядок «wait seeds buffer full»).
2. Виберіть довжину пароля (**digits**) і набори символів: **123** (цифри), **abc** (малі), **ABC** (великі), **.,-!?** (спецсимволи).
3. Натисніть **Generate**. **Show QR** покаже пароль як QR-код, щоб перенести його на телефон.

## Алгоритми перемішування та що вони дають

Безпека пароля має два виміри:

- **Ентропія** — у масі згенерованих паролів вони мають рівномірно розподілятися по можливому простору; це визначає якість. У застосунку єдине джерело ентропії — демодульовані дані AFSK; LCG, SHA-512 і перемішування ентропії не додають.
- **Випадковість** — визначає загальну кількість можливих варіантів. Єдине джерело — алгоритм «кожен символ з окремим зерном із буфера», який розподіляє комбінації на максимальну кількість: (кількість_символів)^(довжина).

| Алгоритм / джерело | Дає ентропію? | Дає випадковість? | Ускладнює зворотне обчислення? | Ускладнює перебір? | Складність (час / пам'ять) |
|---|---|---|---|---|---|
| Час як зерно для вибору випадкової частоти через LCG для отримання AFSK | 🚫 | ✅ | 🚫 | 🚫 | O(1) – O(1) |
| Оригінальні демодульовані дані AFSK як зерна | ✅ | 🚫 | 🚫 | 🚫 | O(1) – O(1) |
| Кожен символ — окреме зерно з буфера | ✅ | 🚫 | 🚫 | ✅ | O(n^довжина) – O(n^довжина) |
| Алгоритм LCG зі стандартної бібліотеки C++ | 🚫 | ✅ | 🚫 | 🚫 | O(n) – O(1) |
| Перемішування двома групами зерен | 🚫 | ✅ | 🚫 | ✅ | O(n) – O(n) |
| Хеш SHA-512 | 🚫 | ✅ | ✅ | 🚫 | O(n) – O(1) |
| **Разом** | ✅ × 2 | ✅ × 4 | ✅ × 1 | ✅ × 2 | |
