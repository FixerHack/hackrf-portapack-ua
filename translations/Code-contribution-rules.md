# Правила внеску коду

## Застереження

Роблячи внесок, ви погоджуєтеся надавати код, що відповідає наведеним нижче правилам. Будь-який pull request може бути призупинений до виправлення. Для всіх — і для учасників, і для рецензентів — важливо мати чистий лог компіляції, щоб легко помічати й виправляти нові проблеми та попередження.

## Правила

- Робіть відступи в коді. Рекомендовано автоматичні відступи, принаймні для нових застосунків.
- Перевіряйте й враховуйте код повернення щоразу, коли це потрібно.
- Реалізуйте обробку помилок у своєму застосунку.
- Робіть повторно використовуваний код (класи, структури, функції-наповнювачі GUI тощо).
- Документуйте і загальну логіку, і хитрі місця. Не лінуйтеся — хтось може розвинути ваш внесок. Інформація всередині коду дуже цінується.
- Виправте всі попередження компіляції **перед** pull request. Усі до одного. Кожен прийнятий PR із купою попереджень робить страшний шум у логах.
- Надавайте доступ до джерел через публічний репозиторій.
- **!! НІКОЛИ не використовуйте `std::rand` чи `std::srand` — відомо, що вони ламають купу/стек/пам'ять !!**

## Код від ШІ

Ми любимо й вітаємо код від ШІ, якщо:

- він не порушує умови використання постачальника й моделі ШІ;
- він суттєво не нагадує й не дублює код з ліцензією, несумісною з ліцензіями цього проєкту;
- ви переглянули код;
- ви зрозуміли код;
- ви протестували код;
- **ви перевірили, що код від ШІ НЕ використовує `std::rand` чи `std::srand`!**

## Про pull request'и

- PR мають бути актуальними щодо гілки `next`.
- Кожна нова функціональність має мати власний PR; не кладіть забагато файлів/комітів в один PR. Коли комітів забагато, можна зробити нову гілку й подати лише змінені файли одним комітом — так легше рецензувати.
- Злиття будь-якого PR — на розсуд мейнтейнерів.

## Правила іменування та використання

- Використовуйте англійську.
- `var_and_func_example` (snake_case)
- `_private_member_of_class_example` (_snake_case)
- `namespaceexample`
- `ClassNameExample` (CamelCase)
- `objectNameExample` (camelCase)
- `func_arg_ex` (snake_case; абревіатури дозволені в коротких функціях)
- Не використовуйте ключове слово `typedef` у C++-коді.
- `goto` заборонено.

## Які ліцензії коду безпечно використовувати

- **MIT** — безпечно копіювати, якщо зберігаєте оригінальну інформацію про авторські права.
- **MPL** — безпечно, якщо дотримуєтесь угоди Mozilla.
- **GNU (GPL 2/3 / AGPL)** — проєкт під GPL, тож GPL-код використовувати безпечно, якщо ви відкриваєте вихідники під GPL.
- **The Unlicense** — безпечно.
- **BSD** — безпечно.
- **WTFPL** — безпечно.
- **CC0** — безпечно.
