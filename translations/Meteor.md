# Meteor LRPT (метеосупутники Meteor-M2)

**Meteor LRPT** — зовнішній застосунок приймання для супутників серії **Meteor-M2**, що передають **LRPT** (Low Rate Picture Transmission) біля **137 МГц**. Він працює з радіо в широкосмуговому режимі, декодує бітовий потік LRPT на процесорі основної смуги **M4** і може **записувати** декодовані дані на SD-карту. Необов'язкова обробка **MSU-MR** (видиме зображення) виконується на ядрі **M0** і може записувати файли **BMP** та показувати невеликий перегляд на екрані.

**Де знайти:** Receive → Meteor LRPT.

> [!NOTE]
> Застосунок новий; інструменти й двійкові файли — у [PR #3175](https://github.com/portapack-mayhem/mayhem-firmware/pull/3175).

Це [зовнішній застосунок](External-apps-informations) (файл `.ppma` на SD-карті).

!!! info "Актуально для України"
    Супутники Meteor-M2 (Росія) досі працюють, тож цей застосунок може приймати реальні зображення над Україною. Потрібна антена з правою круговою поляризацією (RHCP), наприклад QFH на 137 МГц.

## Антена й частота

- LRPT **Meteor M2-3 / M2-4** зазвичай приймають біля **137,9 МГц** (основна). На деяких прольотах може з'являтися резервна лінія біля **137,1 МГц** — перевіряйте актуальну інформацію про супутник.
- У репозиторії є готовий файл Freqman: `sdcard/FREQMAN/METEOR_LRPT.TXT`. Див. [Freq manager](Freq-manager) і [Вміст SD-карти](SD-Card-Content).

## Основні елементи керування

- **Frequency** — центральна частота LRPT (клавіатура або енкодер).
- **RF Amp / LNA / VGA** — як в інших приймачах. Якщо нічого не декодується, не перевантажуйте вхідний каскад. Див. [Проблеми з якістю приймання](Help!-Im-not-receiving-anything!---Receive-Quality-Issues).
- **Volume** — гучність.

## Прапорці декодера

- **M2-x** — для LRPT у стилі Meteor M2-x.
- **Interlv** — режим з перемежуванням M2-x (разом із робочим деперемежуванням на M0).
- **Diff** — диференційне декодування NRZ-M.
- **Leg.corr** — застарілий корелятор (для прийомів не в стилі M2-x).
- **80k sym** — лише для тестових режимів 80 ксимволів/с. Для звичайних прольотів (72 ксимволи/с) вимкніть.
- **BMP** — зберігає тонку сіру смугу за евристикою перегляду JPEG на M4 — **не** повноцінне кольорове зображення MSU-MR. Для справжніх зображень використовуйте MSU-MR.

## Смуга / водоспад

Застосунок очікує смугу в стилі SPEC для LRPT (зазвичай 150 кГц або 250 кГц). Дуже широкі смуги збільшують навантаження на процесор і SD-карту; якщо запис збоїть, зменште смугу або візьміть швидшу SD-карту.

## Запис — CADU і SOFT

Можуть з'явитися два рядки запису:

- **CADU** — записує кадри CADU по 1020 байтів (після Ріда-Соломона). «Сирі» байти мають розширення `.C8`.
- **SOFT** — записує знакові 8-бітові «м'які» символи (пари I/Q) для офлайн-порівняння чи налагодження.

**Важливо:** не вмикайте запис CADU і SOFT одночасно — основна смуга надає лише один потік захоплення за раз.

Розмір блоків для файлів SOFT: 16384 байти — для не перемеженого шляху M2-x; 8192 байти — для M2-x з перемежуванням.

## Структура на SD-карті

Записи й зображення за замовчуванням потрапляють у теку `/LRPT` на SD-карті. Перед довгими прольотами переконайтеся, що карту відформатовано й на ній є місце (див. [Як відформатувати SD-карту](How-to-Format-SDCard)).

## MSU-MR (G4) — зображення на SD

Коли ввімкнено **MSU-MR**, воркер на M0 сканує дані CADU, видобуває корисне навантаження JPEG MSU-MR, декодує базовий JPEG і записує 24-бітові BMP, наприклад `/LRPT/msumr_<apid>_<timestamp>.bmp`.

Короткий порядок дій оператора:

1. Запишіть **CADU** рядком запису CADU під час прольоту (рекомендовано для чистого архіву).
2. Шлях за замовчуванням для воркера — `/LRPT/g4_cadu.C8`; вкажіть на свій запис CADU або змініть **Path**, якщо ім'я інше.
3. Увімкніть **MSU-MR** і стежте за лічильниками в рядку стану.
4. **Live** — необов'язковий режим, де post-RS CADU подається з M4 у невеликий кільцевий буфер RAM для майже реального декодування. Якщо M0 не встигає, частина CADU відкидається (для архіву краще спершу записувати на SD).
5. **Img** та **^** / **v** — переглядач останнього декодованого BMP.

Прогресивний JPEG не підтримується.

## Усунення несправностей

- **Немає декодування / рівний водоспад:** перевірте частоту для **поточного** супутника, антену RHCP, підсилення (без обмеження) і прапорці M2-x / Interlv / 80k відповідно до прольоту.
- **Запис збоїть / жовтий REC:** зменште смугу SPEC, візьміть швидшу SD-карту, скоротіть кабель або записуйте C8.
- **MSU-MR не пише BMP:** перевірте шлях до файлу CADU, стан синхронізації й що JPEG базовий (не прогресивний).
